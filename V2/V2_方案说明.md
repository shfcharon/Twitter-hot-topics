# V2 方案说明文档

## 概述

`pipeline_v2.py` 是基于 V1 Advanced 的 V2-A 方案实现，核心目标是**输出"人类理解的热点讨论议题"**，而不是简单的符号聚合（hashtag/domain/cashtag）。

## V1 存在的问题

### 问题 A：hash 不稳定导致聚类漂移

**问题**：`simple_text_embedding()` 使用了 Python 内置 `hash(word)`，而 Python 的 hash 默认带随机种子（每次进程启动都不同），导致同样的文本今天映射到的向量和明天可能不一样。

**影响**：DBSCAN/HDBSCAN 的簇会漂移，"同一个热点"在输出里每天换 ID、换归属，人工标注也很难闭环。

**V2 解决方案**：使用 `hashlib.md5()` 替代 Python 内置 hash，确保 hash 值稳定。

### 问题 B：DBSCAN + StandardScaler + cosine 的组合容易"过度碎裂"

**问题**：
- `StandardScaler()` 把每一维按均值方差拉伸
- 然后 `DBSCAN(metric='cosine', eps=0.4)`
- 但对 cosine 距离来说，最关键的是"方向"，StandardScaler 可能把一些维度噪声放大，导致方向变形
- 再叠加 DBSCAN 对 eps 很敏感 → 很容易大量点变成 -1 噪声点 → 输出簇数量爆炸，每个簇像"一个网页链接/一个 hashtag"

**V2 解决方案**：使用 `AgglomerativeClustering` 替代 DBSCAN + StandardScaler，直接计算 cosine 距离，不进行标准化。

### 问题 C：topic_text 的构造会把"同一事件"拉得更散

**问题**：`get_topic_text()` 对 hashtag/domain/cashtag 只拼最多 5 条 related_text。如果一个事件被很多 KOL 用不同表述讨论：
- 前 5 条不一定覆盖主叙事
- 5 条可能还包含大量 `<URL>`、无信息转推语
- → embedding 更像"随机采样"，簇更散

**V2 解决方案**：改为事件候选（EventCandidate）为中心，每个事件候选是一组 tweet_id，而不是单个符号。

### 问题 D：content_keyword 的过滤逻辑会错杀 / 也会引入垃圾

**问题**：
- 错杀：比如 "inference / CUDA / datacenter / H100 / open-source / checkpoint" 很可能不在关键词表里 → 被过滤掉
- 放进垃圾：像 "cloud / market / product / growth" 这种泛词在表里 → 大量进入候选，导致簇变成"泛概念堆砌"

**V2 解决方案**：改进过滤逻辑，使用实体（tickers、公司名）和关键短语（bigram/trigram）作为高精召回，而不是简单的关键词匹配。

### 问题 E：topic 层级问题（符号 vs 事件）

**问题**：现在的语义聚类是在 topic（符号）层做，而不是在事件/议题（discussion）层做。即便语义聚类做得完美，它最终也会偏向输出：
- `"#ai"`
- `"openai.com"`
- `"$NVDA"`

而不是：
- `"OpenAI 发布/泄露某新模型，引发 KOL 讨论其商业化与算力供给"`
- `"NVDA 财报/产能/Blackwell 交付节奏与云厂商 CapEx"`

**V2 解决方案**：从符号为中心升级为事件候选为中心，聚类对象从"符号"改为"事件"。

## V2-A 方案设计

### 核心思想

把 "topic candidates" 从**符号（hashtag/domain）为中心**，升级为 **"事件候选（EventCandidate）为中心"**。
符号仍然保留，但它只是事件的特征，而不是事件本体。

### Pipeline 流程

**保留的步骤**：
- Step C: ETL 清洗与标准化
- Step D: 传播关系派生
- Step H: 趋势判断（适配 events）

**替换的步骤**：
- Step E2: 生成事件候选（EventCandidate）
- Step F2: 两阶段聚类（Tweet→Event→Merge）
- Step G2: 事件打分（EventScore）
- Step I2: 事件呈现（title/one_liner/key_entities/evidence_tweets/why_trending）

## Step E2: 生成事件候选（EventCandidate）

### 输入
- `tweets_24h_clean.jsonl` - 24小时清洗后的推文
- `edges_24h.jsonl` - 24小时传播边

### 处理流程

1. **对每条 tweet 构造 doc**：
   - `doc_text = clean_text`（保留关键实体：$TICKER、#hashtag、@mention，但去掉纯 url 噪声）

2. **抽取 features**：
   - **entities**：tickers/hashtags/domains/mentions/companies
   - **关键短语**：bigram/trigram（使用简单 PMI）

3. **两步召回**：
   - **高精召回（Precision seeds）**：
     - tickers（cashtags）
     - 强实体（OpenAI/NVIDIA/Apple…）
     - 高质量 bigram/trigram（包含资本科技关键词的）
   - **语义召回（Recall expansion）**：通过两阶段聚类实现

4. **输出**：
   - `event_candidates_24h.jsonl`：每个候选是一组 tweet_id，包含实体、关键短语等特征

### 输出格式

```json
{
  "event_id": "ev_0001",
  "seed_key": "ticker:NVDA",
  "tweet_ids": ["tweet_id_1", "tweet_id_2", ...],
  "entities": {
    "tickers": ["NVDA"],
    "hashtags": ["ai", "chip"],
    "domains": ["nvidia.com"],
    "mentions": ["nvidia"],
    "companies": ["NVIDIA"]
  },
  "key_phrases": ["blackwell shipment", "gpu capacity", ...]
}
```

## Step F2: 两阶段聚类（Tweet→Event→Merge）

### Stage-1: Tweet 级别聚类

**方法**：
- 使用 embedding（稳定的 `simple_text_embedding` 或 OpenAI embedding）
- 使用 `AgglomerativeClustering`（比 DBSCAN 更稳，能自动处理不同密度）
- 直接计算 cosine 距离，**不进行 StandardScaler**
- `distance_threshold=0.3`（表示 cosine_similarity >= 0.7 的会被合并）

**输出**：Stage-1 簇（每个簇是一组 tweet_id）

### Stage-2: Event 合并

对 Stage-1 的簇再做一次合并，依据：
1. **共享实体**：tickers/公司名/产品名
2. **共享关键短语**：至少 2 个共享短语
3. **簇间 centroid 的 cosine 相似度**（可选）

**输出**：`events_24h.jsonl`（这才是真正的"热点讨论话题"）

### 输出格式

```json
{
  "event_id": "ev_0001",
  "tweet_ids": ["tweet_id_1", "tweet_id_2", ...],
  "entities": {
    "tickers": ["NVDA"],
    "hashtags": ["ai", "chip"],
    "domains": ["nvidia.com"],
    "mentions": ["nvidia"],
    "companies": ["NVIDIA"]
  },
  "key_phrases": ["blackwell shipment", "gpu capacity", ...]
}
```

## Step G2: 事件打分（EventScore）

### 计算公式

```
EventScore = w1*log(engagement) + w2*author_cnt + w3*propagation + w4*novelty + w5*coherence
```

其中：
- **engagement**：`total_likes + total_reposts * 2 + total_replies * 0.5 + total_quotes * 1.5`
- **author_cnt**：参与讨论的不同 KOL 数量
- **propagation**：跨作者传播强度（edges 中"跨作者传播"次数）
- **novelty**：相对历史的新颖度（简化版：`log1p(tweet_cnt) * log1p(author_cnt)`）
- **coherence**：簇内相似度均值（防止"乱炖簇"）

### 硬过滤

1. **author_cnt < 2 且 engagement < 50**：跳过（除非 engagement 爆炸）
2. **coherence < 0.2 且 tweet_cnt >= 3**：跳过（防止"拼凑簇"）

### 输出

- `hot_events_top5_v2.json`：Top5 热点事件

## Step I2: 事件呈现

### 为每个事件生成

1. **title**：用实体 + 关键短语生成（而不是 #tag）
   - 例如：`"NVIDIA / $NVDA / blackwell shipment 等话题"`

2. **one_liner**：一句话说明争论点/事件点
   - 从最热门的推文中提取前100个字符

3. **key_entities**：公司/产品/人名/ticker
   - `{"companies": [...], "tickers": [...], "hashtags": [...], "domains": [...]}`

4. **evidence_tweets**：按影响力排序的 5 条推文

5. **why_trending**：burst + 传播链解释
   - 例如：`"3 位 KOL 参与讨论；跨作者传播 5 次；总互动量 150"`

### 输出

- `daily_report_v2.json`：完整报告
- `daily_report_readable_v2.json`：易读版本（中文）

## V2 vs V1 核心区别

| 方面 | V1 Advanced | V2 |
|------|-------------|-----|
| **候选对象** | 符号（hashtag/domain/cashtag） | 事件候选（一组 tweet_id） |
| **聚类对象** | Topic（符号） | Event（事件） |
| **Hash 函数** | Python 内置 hash（不稳定） | hashlib.md5（稳定） |
| **聚类算法** | DBSCAN + StandardScaler + cosine | AgglomerativeClustering + cosine（无 StandardScaler） |
| **聚类阶段** | 单阶段 | 两阶段（Tweet→Event→Merge） |
| **打分方式** | HotScore（基于 topic） | EventScore（基于 event，包含 coherence） |
| **标题生成** | 关键词列表 | 实体 + 关键短语 |
| **描述** | 统计信息 | one_liner（一句话说明） |
| **输出内容** | 符号聚合 | 真实讨论议题 |

## 技术细节

### Hash 稳定性修复

**V1**：
```python
hash_val = hash(word) % 256  # 不稳定
```

**V2**：
```python
hash_obj = hashlib.md5(word.encode('utf-8'))
hash_val = int(hash_obj.hexdigest(), 16) % 256  # 稳定
```

### 聚类算法改进

**V1**：
```python
scaler = StandardScaler()
embeddings_scaled = scaler.fit_transform(embeddings_matrix)
clustering = DBSCAN(eps=0.4, min_samples=min_cluster_size, metric='cosine')
```

**V2**：
```python
# 不进行 StandardScaler
clustering = AgglomerativeClustering(
    n_clusters=None,
    distance_threshold=0.3,  # cosine distance threshold
    linkage='average',
    metric='cosine'
)
```

## 总结

V2-A 方案通过以下改进，实现了从"符号聚合"到"真实讨论议题"的升级：

1. **修复 hash 不稳定**：使用稳定的 hash 函数
2. **改进聚类算法**：使用 AgglomerativeClustering，避免 StandardScaler 问题
3. **事件候选为中心**：从符号升级为事件
4. **两阶段聚类**：Tweet→Event→Merge，更准确地识别事件
5. **事件打分**：EventScore 包含 coherence，防止"拼凑簇"
6. **更好的呈现**：title/one_liner/key_entities/evidence_tweets/why_trending

最终输出的是**"人类理解的热点讨论议题"**，而不是简单的标签列表。

# V2 聚类问题分析与新方案（最终版）

## 一、问题本质分析

### 1.1 核心认知

**你不是在做"文本聚类"，你是在做"现实世界事件的自动归纳"。**

当前问题的本质：
- ❌ 不是"聚类算法选错了"
- ❌ 不是"embedding 不够好"
- ✅ 而是：**非结构化文本的聚类目标，本来就不是一个纯算法问题**

### 1.2 为什么纯代码会失败

**热点 ≠ 高频**
- 高频的可能是平台域名、泛词

**热点 ≠ 语义相似**
- 语义相似但讲不同事件（如"GPT-5发布" vs "GPT-5评测"）

**热点 = 多人对同一变化形成共识**
- 这是一个**社会认知问题**，不是向量问题

### 1.3 设计哲学

**V2 的设计哲学**：
- 事件级视角：聚焦现实世界事件，不是文本相似度
- 传播锚点优先：完全结构化，无语义歧义
- 人类认知流程：不依赖 embedding，基于结构化条件
- **人工资产层前置**：人工定义世界，而不是修补结果

## 二、最终版 V2 完整可落地方案

### 2.1 方案架构

```

  ↓
Step 0: 人工资产层（必须新增）
  - Frontier Entity Dictionary（人工维护）
  - Frontier Action Verbs（人工维护）
  - Hard Stop Words / Platform Blacklist（必须完整）
  ↓
Step 1: 事件候选生成（受限）
  - 一条 tweet = 一个 EventCandidate
  - entity ∈ Entity Dictionary（必须命中）
  - action ∈ Action Verbs（必须命中）
  - 否则直接丢弃
  ↓
Step 2: 强规则过滤（升级）

  ↓
Step 4: 增量式事件合并（结构化权重层级）
  - 合并条件按优先级排序
```

- **人工最有价值的地方是：定义世界，而不是修补结果**

#### 创新 2：事件级而非符号级
- **最小单元**：一条 tweet（不是 hashtag/domain）
- **聚类对象**：事件（不是文本相似度）
- **判断标准**：是否指向同一现实事件

#### 创新 3：传播锚点优先
- **被多个 KOL 转发/引用的 tweet = 事件锚点**
- **所有指向它的 tweet 自动属于同一事件**
- **完全结构化、无语义歧义**
- **anchor cluster 权重最高**

#### 创新 4：结构化权重层级
- **合并条件按优先级排序**，不是所有条件等权
- **同一 anchor（最强）**
- **语义确认（最弱）**

### 3.2 Step 1: 事件候选生成（保留，受限）

#### 目标
将每条 tweet 转换为事件候选，但**必须受限**。

#### 处理逻辑
```python
EventCandidate = {
    "event_id": "tweet_id",
    "entity": ["OpenAI", "GPT-5"],  # 必须来自 Entity Dictionary
    "action": "release",  # 必须来自 Action Verbs
    "time": timestamp,
    "text": "clean_text",
    "author": "author_username",
    "is_anchor": false,
    "referenced_tweet_id": null
}
```

#### 关键规则
1. **entity 必须来自 Entity Dictionary**
   - ❌ 不是「从文本里提 entity」
   - ✅ 而是「文本是否命中了我认可的 entity 集合」
   - 如果未命中，直接丢弃

2. **action 必须来自 Action Verbs**
   - 如果未命中，直接丢弃

3. **判断传播锚点**
   - 如果 tweet 被其他 tweet 引用（在 edges_24h 中作为 target）
   - 且被引用次数 ≥ 1（可调整）
   - 则标记为 `is_anchor = true`

### 3.3 Step 2: 强规则过滤（升级）

#### 硬规则（100% 自动，命中即丢）

直接排除 EventCandidate，如果满足**任一条**：

1. **entity_valid = false**
   - entity 未命中 Entity Dictionary

2. **action_valid = false**
   - action 未命中 Action Verbs

3. **命中 platform domain**
   - domain 在 Platform Blacklist 中

4. **文本只有 URL / domain**
   - 文本去除 URL 后为空或只有空格

5. **只有泛词**
   - 文本只包含 Hard Stop Words 中的词

#### 规则特点
- **Hard Drop Rules**：任何一条命中，永不进入聚类
- **不可逆闸门**：一旦命中，直接丢弃，不再处理

### 3.4 Step 3: 传播锚点聚类（完全保留）

#### 核心思想
**被多个 KOL 转发/引用的 tweet = 事件锚点**
**所有指向它的 tweet 自动属于同一事件**

#### 处理流程
```python
# 1. 识别传播锚点
anchors = []
for tweet in filtered_candidates:
    if tweet.is_anchor and tweet.reference_count >= 1:  # 可调整
        anchors.append(tweet)

# 2. 为每个锚点创建事件簇
event_clusters = []
for anchor in anchors:
    cluster = {
        "cluster_id": anchor.event_id,
        "cluster_type": "anchor",
        "anchor_tweet": anchor,
        "event_ids": [anchor.event_id],
        "authors": [anchor.author],
        "entity": anchor.entity,
        "action": anchor.action,
        "weight": 10.0  # anchor cluster 权重最高
    }
    
    # 3. 找到所有指向这个锚点的 tweet
    for edge in edges_24h:
        if edge.target_tweet_id == anchor.event_id:
            source_tweet = find_tweet(edge.source_tweet_id)
            if source_tweet:
                cluster.event_ids.append(source_tweet.event_id)
                cluster.authors.append(source_tweet.author)
    
    event_clusters.append(cluster)
```

#### 优势
- ✅ **完全结构化**：基于传播关系，无语义歧义
- ✅ **天然符合热点定义**：多人讨论同一件事
- ✅ **权重最高**：anchor cluster 权重高于任何非 anchor cluster

### 3.5 Step 4: 增量式事件合并（结构化权重层级）

#### 核心思想
**模仿人类读推文的过程**，但使用**结构化权重层级**。

#### 合并条件（按优先级，从强到弱）

1. **同一 anchor（最强）**
   - 如果两条 tweet 都指向同一个 anchor
   - 权重：10.0
   - 自动合并

2. **同一 entity + 同一 action**
   - `tweet1.entity == tweet2.entity` 且 `tweet1.action == tweet2.action`
   - 权重：8.0
   - 自动合并

3. **同一 entity + 时间接近**
   - `tweet1.entity == tweet2.entity` 且 `|tweet1.time - tweet2.time| <= 48h`
   - 权重：6.0
   - 自动合并

4. **不同 KOL + 时间接近 + action 相同**
   - `tweet1.author != tweet2.author` 且 `|tweet1.time - tweet2.time| <= 48h` 且 `tweet1.action == tweet2.action`
   - 权重：4.0
   - 自动合并

5. **（可选）语义相似度 ≥ 0.7（最弱）**
   - 只在通过前面条件后，才计算语义相似度
   - 权重：2.0
   - 默认关闭，仅用于确认

#### 处理流程
```python
topics = []  # 已有主题列表

for tweet in remaining_tweets:  # 剩余未聚类的 tweet
    merged = False
    best_match = None
    best_weight = 0.0
    
    for topic in topics:
        # 检查合并条件（按优先级）
        weight = 0.0
        condition = None
        
        # 条件1: 同一 anchor（最强）
        if tweet.anchor_id and topic.anchor_id and tweet.anchor_id == topic.anchor_id:
            weight = 10.0
            condition = "同一anchor"
        
        # 条件2: 同一 entity + 同一 action
        elif tweet.entity == topic.entity and tweet.action == topic.action:
            weight = 8.0
            condition = "同一entity+action"
        
        # 条件3: 同一 entity + 时间接近
        elif tweet.entity == topic.entity and abs(tweet.time - topic.avg_time) <= 48 * 3600:
            weight = 6.0
            condition = "同一entity+时间接近"
        
        # 条件4: 不同KOL + 时间接近 + action相同
        elif (tweet.author != topic.representative.author and 
              abs(tweet.time - topic.avg_time) <= 48 * 3600 and
              tweet.action == topic.action):
            weight = 4.0
            condition = "不同KOL+时间接近+action相同"
        
        # 选择权重最高的匹配
        if weight > best_weight:
            best_weight = weight
            best_match = (topic, condition)
    
    # 如果找到匹配，合并
    if best_match and best_weight >= 4.0:  # 最低阈值
        topic, condition = best_match
        topic.merge(tweet, condition)
        merged = True
    
    # 如果没有合并，创建新主题
    if not merged:
        topics.append(create_new_topic(tweet))
```

#### 优势
- ✅ **结构化权重层级**：不是所有条件等权
- ✅ **符合人类认知**：模仿人类分类过程
- ✅ **可解释性强**：每一步都有明确的权重和条件

### 3.6 Step 5: 受限语义确认（默认关闭）

#### 使用场景
- 仅用于人工标记"可能重复"的 topic
- 不作为自动合并依据
- 作为 debug / sanity check

#### 处理逻辑
```python
# 默认关闭
USE_SEMANTIC_CONFIRMATION = False

# 只在人工标记为"可能重复"时使用
if USE_SEMANTIC_CONFIRMATION and topic.human_marked_as_duplicate:
    similarity = cosine_similarity(embedding1, embedding2)
    if similarity >= 0.7:

```

### 3.7 Step 6: 半人工校正（必须）

#### 核心思想
**允许模型聚，但由人来"命名 & 合并"**

#### 流程
1. **模型生成 20-30 个候选簇**
2. **人工做三件事**（10分钟完成）：
   - 合并重复的
   - 删掉废话的
   - 给剩下的命名

#### 输出格式
```json
{
  "candidate_clusters": [
    {
      "cluster_id": 1,
      "event_ids": [...],
      "suggested_title": "GPT-5 在 Codex 中的突破",
      "key_entities": ["GPT-5", "Codex"],
      "human_action": "keep" | "merge" | "delete",
      "human_title": "..."
    }
  ]
}
```

#### 优势
- ✅ **快速验证**：10分钟完成人工校正
- ✅ **保证质量**：最终输出一定是人类认可的
- ✅ **可迭代**：根据人工反馈调整规则

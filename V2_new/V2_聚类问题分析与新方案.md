# V2 聚类问题分析与新方案

## 一、问题本质分析

### 1.1 核心认知

**你不是在做"文本聚类"，你是在做"现实世界事件的自动归纳"。**

当前问题的本质：
- ❌ 不是"聚类算法选错了"
- ❌ 不是"embedding 不够好"
- ✅ 而是：**非结构化文本的聚类目标，本来就不是一个纯算法问题**

### 1.2 为什么纯代码会失败

**热点 ≠ 高频**
- 高频的可能是平台域名、泛词

**热点 ≠ 语义相似**
- 语义相似但讲不同事件（如"GPT-5发布" vs "GPT-5评测"）

**热点 = 多人对同一变化形成共识**
- 这是一个**社会认知问题**，不是向量问题

## 二、新方案设计：整合三种方法

### 2.1 方案架构

```
输入: tweets_24h_clean.jsonl
  ↓
Step 1: 事件候选生成（Event-Centric）
  - 每条 tweet = 一个事件候选
  - 提取 <entity, action, time> 三元组
  ↓
Step 2: 强规则过滤（Rule-First）
  - 排除平台域名、泛词、无实体无动作
  ↓
Step 3: 传播锚点聚类（Event-Centric + Human-Style）
  - 以"被引用 tweet"为中心
  - 所有指向它的 tweet 自动属于同一事件
  ↓
Step 4: 增量式主题形成（Human-Style）
  - 对剩余 tweet，按人类认知流程合并
  - 使用结构化条件（≥2条）判断是否同一事件
  ↓
Step 5: 受限语义确认（Optional）
  - 只在通过结构化条件后，才用语义相似度确认
  ↓
Step 6: 半人工校正（Human-in-the-loop）
  - 生成 20-30 个候选簇
  - 人工合并重复、删除废话、命名
```

### 2.2 核心创新点

#### 创新 1：事件级而非符号级
- **最小单元**：一条 tweet（不是 hashtag/domain）
- **聚类对象**：事件（不是文本相似度）
- **判断标准**：是否指向同一现实事件

#### 创新 2：传播锚点优先
- **被多个 KOL 转发/引用的 tweet = 事件锚点**
- **所有指向它的 tweet 自动属于同一事件**
- **完全结构化、无语义歧义**

#### 创新 3：人类认知流程
- **增量式主题形成**：模仿人类读推文的过程
- **结构化条件**：≥2 条条件才合并
- **不依赖 embedding**：可以完全不用

#### 创新 4：规则先行、语义兜底
- **规则决定候选集合**
- **语义只负责确认**
- **embedding 权重很低**

## 三、详细方案设计

### 3.1 Step 1: 事件候选生成（Event-Centric）

#### 目标
将每条 tweet 转换为事件候选，提取 `<entity, action, time>` 三元组。

#### 处理逻辑
```python
EventCandidate = {
    "event_id": "tweet_id",
    "entity": ["OpenAI", "GPT-5"],  # 实体列表
    "action": "release",  # 动作类型
    "time": timestamp,
    "text": "clean_text",
    "author": "author_username",
    "is_anchor": false,  # 是否是传播锚点
    "referenced_tweet_id": null  # 如果引用其他tweet
}
```

#### 实体提取
- **Companies**: 从文本匹配公司名白名单
- **Products**: 从文本匹配技术产品白名单
- **Tickers**: 从 cashtags 提取
- **People**: 从 mentions 提取（如果是知名人物）

#### 动作提取
使用 `FRONTIER_ACTION_VERBS` 列表：
- launch / release / announce / ship
- leak / rumor / benchmark
- acquire / invest / raise

#### 判断传播锚点
- 如果 tweet 被其他 tweet 引用（在 edges_24h 中作为 target）
- 且被引用次数 ≥ 2
- 则标记为 `is_anchor = true`

### 3.2 Step 2: 强规则过滤（Rule-First）

#### 硬规则（100% 自动）
直接排除，如果满足任一条：
1. 文本只有 URL / domain
2. 转推模板（"RT @" 开头）
3. domain 属于平台型（google.com, x.com 等）
4. 没有任何实体 + 没有动作词
5. 只有泛词（AI / cloud / market）

### 3.3 Step 3: 传播锚点聚类（Event-Centric）

#### 核心思想
**被多个 KOL 转发/引用的 tweet = 事件锚点**
**所有指向它的 tweet 自动属于同一事件**

#### 处理流程
```python
# 1. 识别传播锚点
anchors = []
for tweet in filtered_candidates:
    if tweet.is_anchor and tweet.reference_count >= 2:
        anchors.append(tweet)

# 2. 为每个锚点创建事件簇
event_clusters = []
for anchor in anchors:
    cluster = {
        "cluster_id": anchor.event_id,
        "anchor_tweet": anchor,
        "event_ids": [anchor.event_id],
        "authors": [anchor.author],
        "entity": anchor.entity,
        "action": anchor.action
    }
    
    # 3. 找到所有指向这个锚点的 tweet
    for edge in edges_24h:
        if edge.target_tweet_id == anchor.event_id:
            source_tweet = find_tweet(edge.source_tweet_id)
            if source_tweet:
                cluster.event_ids.append(source_tweet.event_id)
                cluster.authors.append(source_tweet.author)
    
    event_clusters.append(cluster)
```

#### 优势
- ✅ **完全结构化**：基于传播关系，无语义歧义
- ✅ **天然符合热点定义**：多人讨论同一件事
- ✅ **可解释性强**：为什么聚在一起？因为有传播关系

### 3.4 Step 4: 增量式主题形成（Human-Style）

#### 核心思想
**模仿人类读推文的过程**：
- 读第一条推文 → 创建主题1
- 读第二条推文 → 问"它是不是在讲同一件事？"
  - 如果是 → 合并到主题1
  - 如果否 → 创建主题2

#### 人类判断条件（结构化）
一条 tweet 可以并入已有 topic，当且仅当满足 **≥2 条**：

1. **提到同一个实体**（公司 / 产品 / 技术）
   - `tweet1.entity ∩ tweet2.entity ≠ ∅`

2. **描述相同类型事件**（发布 / 融资 / 泄露）
   - `tweet1.action == tweet2.action`

3. **时间间隔 < 48h**
   - `|tweet1.time - tweet2.time| <= 48 * 3600`

4. **来自不同 KOL**
   - `tweet1.author != tweet2.author`

5. **被互相转发 / 引用**
   - 在 edges_24h 中存在边连接

#### 处理流程
```python
topics = []  # 已有主题列表

for tweet in remaining_tweets:  # 剩余未聚类的 tweet
    merged = False
    
    for topic in topics:
        # 检查是否满足 ≥2 条条件
        conditions_met = 0
        
        # 条件1: 实体交集
        if tweet.entity ∩ topic.entities:
            conditions_met += 1
        
        # 条件2: 相同动作
        if tweet.action == topic.action:
            conditions_met += 1
        
        # 条件3: 时间接近
        if abs(tweet.time - topic.avg_time) <= 48 * 3600:
            conditions_met += 1
        
        # 条件4: 不同KOL
        if tweet.author not in topic.authors:
            conditions_met += 1
        
        # 条件5: 传播关系
        if has_propagation(tweet, topic):
            conditions_met += 1
        
        # 如果满足 ≥2 条，合并
        if conditions_met >= 2:
            topic.merge(tweet)
            merged = True
            break
    
    # 如果没有合并，创建新主题
    if not merged:
        topics.append(create_new_topic(tweet))
```

#### 优势
- ✅ **不依赖 embedding**：完全基于结构化条件
- ✅ **符合人类认知**：模仿人类分类过程
- ✅ **可解释性强**：每一步都有明确的条件

### 3.5 Step 5: 受限语义确认（Optional）

#### 使用场景
只在通过结构化条件后，才用语义相似度**确认**（不是决定）。

#### 处理逻辑
```python
# 只在满足 ≥2 条结构化条件后
if conditions_met >= 2:
    # 才计算语义相似度
    similarity = cosine_similarity(embedding1, embedding2)
    
    # 如果相似度也很高，增强信心
    if similarity >= 0.7:
        confidence = "high"
    else:
        confidence = "medium"  # 仍然可以合并，但信心较低
```

#### 注意
- **embedding 只起确认作用**，不是决定权
- **阈值可以很高**（0.7+），因为已经有结构化条件保证

### 3.6 Step 6: 半人工校正（Human-in-the-loop）

#### 核心思想
**允许模型聚，但由人来"命名 & 合并"**

#### 流程
1. **模型生成 20-30 个候选簇**
2. **人工做三件事**（10分钟完成）：
   - 合并重复的
   - 删掉废话的
   - 给剩下的命名

#### 输出格式
```json
{
  "candidate_clusters": [
    {
      "cluster_id": 1,
      "event_ids": [...],
      "suggested_title": "GPT-5 在 Codex 中的突破",
      "key_entities": ["GPT-5", "Codex"],
      "human_action": "keep" | "merge" | "delete",
      "human_title": "..."
    }
  ]
}
```

#### 优势
- ✅ **快速验证**：10分钟完成人工校正
- ✅ **保证质量**：最终输出一定是人类认可的
- ✅ **可迭代**：根据人工反馈调整规则

## 四、方案对比

### 4.1 与现有方案对比

| 方面 | V2-B (现有) | 新方案 |
|------|------------|--------|
| **聚类对象** | 文本相似度 | 事件相同 |
| **判断标准** | embedding 相似度 | 结构化条件 + 传播关系 |
| **依赖 embedding** | 高度依赖 | 可选（只确认） |
| **可解释性** | 低 | 高 |
| **人工参与** | 无 | 半人工校正 |
| **聚类质量** | 不稳定 | 稳定可控 |

### 4.2 解决的核心问题

| 问题 | 是否解决 | 如何解决 |
|------|---------|---------|
| domain / google.com 成为 topic | ✅ | 强规则过滤 + 传播锚点优先 |
| topic 像符号不像事件 | ✅ | 事件级聚类 + 增量式主题形成 |
| embedding 聚得"像但不对" | ✅ | 结构化条件优先，embedding 只确认 |
| 结果不可解释 | ✅ | 每一步都有明确条件和决策轨迹 |
| 聚类失控 | ✅ | 规则先行 + 传播锚点约束 |

## 五、实施建议

1. **🔥 最优先**：传播锚点聚类（Step 3）
   - 完全结构化，无语义歧义
   - 天然符合热点定义
   - 实现简单，效果稳定

2. **🔥 次优先**：增量式主题形成（Step 4）

4. **⚡ 必须**：半人工校正（Step 6）
   - 保证最终质量
   - 快速验证方案

### 5.2 实施步骤

   - 验证效果

   - 如果需要，添加语义相似度确认

4. **第四步**：实现半人工校正
   - 生成候选簇
